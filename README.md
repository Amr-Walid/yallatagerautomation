# يلا تاجر — ويب أبلكيشن تسجيل المنتجات

تطبيق ويب (+ سكربت CLI) لتسجيل منتجات البائع على
[yallatager.com](https://yallatager.com) من ملف إكسل واحد.

**سير العمل في الواجهة:**

1. أدخل **بريد وكلمة مرور** حساب التاجر
2. **اختر الفئة** من الفئات الحقيقية في حسابك
3. **نزّل تيمبليت إكسل** جاهز بأعمدة الفئة
4. املأه و**ارفعه** — نبحث بالكود أولاً، وبالاسم لو الكود لم يُعطِ نتيجة
5. شاهد **النتيجة لحظياً**: ما تم تسجيله وما لم يُسجَّل **والسبب**

```bash
npm install && npm start     # ثم افتح http://localhost:3000
```

---

## أعمدة التيمبليت

| العمود | إجباري | الوصف |
|---|---|---|
| كود المنتج (ID / باركود) | — | **يُبحث به أولاً** |
| اسم المنتج | — | **الخطة البديلة** لو الكود لم يُعطِ نتيجة |
| سعر البيع | ✅ | الموقع يرفض التسجيل بدونه |
| سعر الجملة | ✅ | سعر مجموعة Wholesale |
| الكمية | — | اختياري |
| سعر خاص | — | اختياري |
| ملاحظات | — | لك فقط، لا تُرسل للموقع |

يكفي ملء **الكود أو الاسم** (أحدهما) لكل صف — وبقية البيانات اختيارية
عدا السعرين.

## حماية سيرفر يلا تاجر من الإجهاد

هذا كان أهم قيد في التصميم. الطبقة في `lib/throttle.js` تضمن:

| الآلية | الأثر |
|---|---|
| **طابور تسلسلي** | طلب واحد فقط في اللحظة — لا توجد دفعات متزامنة مهما كان عدد الصفوف |
| **فاصل زمني + jitter** | ~١.١ ثانية بين الطلبات بتشويش عشوائي |
| **ذاكرة مؤقتة (١٥ دقيقة)** | الأكواد/الفئات المكرّرة = صفر طلبات إضافية |
| **قاطع دائرة** | يتوقّف تلقائياً ٢٥ ثانية بعد ٤ أخطاء متتالية |
| **تهدئة تكيّفية** | كل خطأ يضاعف الفاصل، وكل نجاح يقلّله بهدوء |
| **احترام HTTP 429** | يُعالج كخطأ يستدعي التهدئة فوراً |

### استراتيجية "الفهرسة مرة واحدة"

السكربت القديم كان يبحث لكل صف × كل فئة (١٦ صف ⇒ حتى **١٢٨ طلب**).
الآن، للملفات الكبيرة (١٢ صف أو أكثر) نجلب **فهرس الفئة مرة واحدة**
ونطابق كل الصفوف **محلياً في الذاكرة بصفر طلبات بحث**.
وللملفات الصغيرة نستخدم البحث المستهدف لأنه أوفر.

تُعرض إحصائية الاستهلاك في نهاية كل تشغيل (عدد الطلبات، وكم طلب
وُفّر بالذاكرة المؤقتة).

### دقّة المطابقة — لا تخمين

رصدنا خطراً حقيقياً على الموقع: البحث عن `SN-33` يُرجّع
`SN-333` و`SN-336` و`SN-338` **قبل** المنتج الصحيح.
الاعتماد على أول نتيجة كان سيسجّل منتجاً خطأ بسعر منتج آخر.

لذلك المطابقة بالكود تتطلّب **تطابقاً تاماً للكود** (لا احتواء نصي).
وإذا تعدّدت الاحتمالات، نُبلّغ المستخدم بالمرشّحين **ولا نسجّل شيئاً**.

## لماذا كان السكربت القديم لا يعمل؟

السكربت السابق كان يعتمد على **Playwright** لفتح صفحة تسجيل الدخول
والتعامل مع النماذج. المشكلة أن **الموقع نفسه معطوب** ولا يمكن لأي متصفح
الوصول لصفحة الدخول إطلاقاً:

| المسار | النتيجة الفعلية |
|---|---|
| `https://yallatager.com/ar/account/login` | تحويل 302 إلى `/ar` ثم صفحة **404** داخل الـ SPA |
| `https://yallatager.com/ar/login` | HTTP 200 لكن يعرض **404** (ليس مساراً حقيقياً) |
| `https://yallatager.com/ar/vendor/add-products` | **HTTP 500** |
| `https://yallatager.com/account/login` | **HTTP 500** |

سبب الخطأ 500 هو عطل في بناء الموقع (Nuxt 3 SSR):

```json
{
  "statusCode": 500,
  "message": "Named export 'VueTelInput' not found. The requested module
              'vue3-tel-input' is a CommonJS module, which may not support
              all module.exports as named exports."
}
```

**النتيجة:** لا يوجد نموذج تسجيل دخول يمكن للمتصفح فتحه، ولهذا كانت كل
محددات السكربت القديم (`#usernameemail`، `أضف منتجات` … إلخ) تفشل دائماً —
لأنها كانت تُبحث داخل صفحة 404.

### الحل

التعامل مباشرة مع **نفس الـ REST API** الذي يستخدمه الموقع
(`https://backend.yallatager.com/restfulapi/…`). هذا أسرع وأكثر ثباتاً،
ولا يحتاج متصفحاً على الإطلاق. لم نعد نحتاج حزمة Playwright.

## التثبيت

```bash
npm install
```

المتطلبات: **Node.js 18 أو أحدث** (يستخدم `fetch` المدمج).
الاعتماد الخارجي الوحيد هو `xlsx` — السيرفر مبني على وحدات Node الأساسية.

## تشغيل الويب أبلكيشن

```bash
npm start              # المنفذ 3000
PORT=8080 npm start    # منفذ آخر
```

| المسار | الوظيفة |
|---|---|
| `POST /api/login` | تحقّق من التاجر + إرجاع الفئات |
| `POST /api/template` | تنزيل تيمبليت الفئة |
| `POST /api/run` | رفع الملف وبدء التسجيل |
| `GET /api/job/:id/stream` | بثّ التقدّم المباشر (SSE) |
| `GET /api/job/:id/report` | تقرير النتائج بالإكسل |
| `POST /api/job/:id/cancel` | إلغاء العملية |

ملاحظات أمان: بيانات الدخول تُستخدم للاتصال بالموقع فقط ولا تُحفظ على
القرص، والجلسة تنتهي تلقائياً بعد ٣٠ دقيقة، ولا يُسمح بأكثر من عملية
واحدة في نفس الوقت لكل حساب.

## الاستخدام عبر سطر الأوامر (CLI)

```bash
# 1) معاينة: بحث وتحقق فقط بدون إضافة أي منتج (ابدأ من هنا دائماً)
node yalla_tager_automation.js --dry-run

# 2) إضافة فعلية بسعر محدد
node yalla_tager_automation.js --price 1000 --qty 5

# 3) إضافة فعلية بسعر القالب المعروض على الموقع
node yalla_tager_automation.js --use-template-price

# 4) سعر بيع مختلف عن سعر الجملة
node yalla_tager_automation.js --price 1200 --group-price 1000

# 5) تشخيص الاتصال خطوة بخطوة
node tools/diagnose.js
```

### الخيارات

| الخيار | الوصف |
|---|---|
| `-n, --dry-run` | بحث وتحقق فقط، بدون أي حفظ |
| `--price <سعر>` | السعر لكل منتج — **إجباري للحفظ الفعلي** |
| `--use-template-price` | استخدام سعر القالب المعروض بالموقع بدلاً من `--price` |
| `--group-price <سعر>` | سعر مجموعة الجملة (افتراضياً = نفس `--price`) |
| `--qty <عدد>` | الكمية لكل منتج (اختيارية) |
| `--force` | الإضافة حتى لو كان القالب مُرسلاً سابقاً (⚠️ خطر تكرار) |
| `--email` / `--password` | بيانات الدخول (أو عبر `YALLA_EMAIL` / `YALLA_PASSWORD`) |
| `--excel <ملف>` | ملف الإكسل (افتراضياً `YALLA.xlsx`) |
| `--categories <ids>` | أرقام الفئات مفصولة بفواصل (افتراضياً `5,144,145,33`) |
| `--limit` / `--delay` | عدد نتائج البحث / الفاصل الزمني بين الطلبات |

### تنسيق ملف الإكسل

| العمود | المحتوى | مثال |
|---|---|---|
| A | الباركود (SKU) | `6968892300155` |
| B | كود الموديل | `SN-88` |
| C | الوصف (اختياري) | |

السكربت يبحث **بالباركود أولاً** (أدق) ثم **بكود الموديل**.
> السكربت القديم كان يقرأ العمود A فقط، وبعض الباركودات غير مطابقة لأي
> منتج على الموقع — وهذا سبب آخر لفشل البحث.

## قواعد الباك إند المكتشفة

هذه القواعد اكتُشفت بالتجربة العملية وهي أساس عمل السكربت:

### 1. حقل الدخول اسمه `usernameemail`
وليس `username` أو `email`. أي اسم آخر يُرفض.

### 2. `category_id` إجباري في البحث
نداء `epowermarketplace/seller/gettemplates` بدون `category_id` يفشل
**دائماً** بالخطأ `marketplace_sellerproduct_100`. لذلك يجرّب السكربت كل
فئة من قائمة `--categories` حتى يجد المنتج.

### 3. `price` و `group_price` إجباريان معاً للحفظ
نقص أيٍّ منهما يعطي:
```
marketplace_seller_133 — "You must add group prices and validate price."
```
الكمية `quantity` **اختيارية** (يمكن تركها فارغة).

### 4. `group_price` تُبنى من `getCustomerGroups()` لا من القالب
- ✅ `epowermarketplace/seller/getCustomerGroups` ⇒ `[{label:"Wholesale", value:"2"}]`
- ❌ `template.customer_groups` ⇒ `{2:"Wholesale", 7:"Blacklist"}`

المجموعة `2` (Wholesale) وحدها كافية ومقبولة — وهذا ما تفعله صفحة الموقع.

### 5. `seller_id` إجباري في سرد المنتجات
`epowermarketplace/seller/getproducts` بدون `seller_id` يفشل بـ
`marketplace_seller_108 "Cannot load seller."`. رقم التاجر يُجلب من
`getSellerFormData` (هنا `vendor_id = 1053`).

### 6. ⚠️ لا يوجد منع تكرار في الباك إند
كل نداء لـ `createrequest` يُنشئ **طلباً جديداً** بـ `entity_id` جديد، حتى
لو كان نفس القالب ونفس السعر. والأسوأ: الطلبات المعلّقة (`status=2`) **لا
تظهر** في `getproducts` إلا بعد اعتمادها.

لذلك يمنع السكربت التكرار بطريقتين معاً:
1. مطابقة الكتالوج المنشور (`getproducts`)
2. سجل محلي دائم في **`results/submitted.json`** يُحدَّث بعد كل إضافة ناجحة

> ⚠️ لا تحذف `results/submitted.json` — حذفه يعني فقدان الحماية من التكرار.

### 7. معالجة الكوكيز
يجب **حذف** الكوكيز التي قيمتها `deleted` (مثل
`persistent_shopping_cart=deleted`) وإلا تفسد الجلسة.

### 8. أخطاء مؤقتة
`marketplace_sellerproduct_100` يظهر أحياناً بشكل عشوائي، لذلك يعيد
السكربت المحاولة تلقائياً مع تأخير متزايد.

## بنية المشروع

```
server.js                   سيرفر الويب أبلكيشن (Node core فقط)
public/
  index.html                الواجهة العربية RTL
  styles.css                التنسيق
  app.js                    منطق الواجهة + متابعة SSE
yalla_tager_automation.js   السكربت الرئيسي (CLI)
lib/
  api.js                    عميل REST: دخول، بحث، حفظ، سرد، كوكيز، إعادة محاولة
  throttle.js               حماية السيرفر: طابور + فاصل + كاش + قاطع دائرة
  job.js                    مُشغِّل العملية + بثّ التقدّم + اختيار النتيجة الصحيحة
  engine.js                 فهرسة الفئة + مطابقة محلية (عربي/إنجليزي)
  template.js               بناء وقراءة تيمبليت الإكسل
  excel.js                  قراءة الباركود + كود الموديل (الصيغة القديمة)
  state.js                  سجل منع التكرار
  logger.js                 تسجيل ملوّن + ملف
tools/
  diagnose.js               تشخيص الاتصال في 8 خطوات
  test_all_codes.js         التحقق من وجود كل أكواد الإكسل
results/
  submitted.json            ← سجل منع التكرار (مهم، لا تحذفه)
  report-<التاريخ>.json      تقرير كل تشغيل
logs/run.log                سجل التشغيل
```

## المخرجات

- `results/report-<التاريخ>.json` — تقرير مفصّل لكل صف: رقم القالب، السعر
  المُرسَل، رقم الطلب، أو سبب الفشل.
- `results/submitted.json` — سجل منع التكرار.
- `logs/run.log` — سجل نصي لكل التشغيلات.

### حالات الصفوف في التقرير

| الحالة | المعنى |
|---|---|
| `saved` | تمت الإضافة بنجاح |
| `dry_run_ok` | جاهز للإضافة (وضع المعاينة) |
| `already_published` | موجود بالكتالوج المنشور — تم التخطي |
| `already_submitted` | أُرسل سابقاً حسب السجل المحلي — تم التخطي |
| `not_found` | لا يوجد قالب مطابق على الموقع (أو نتائج غامضة لم نُخمّن فيها) |
| `no_price` | عمود سعر البيع فارغ ولا سعر على الموقع |
| `missing_key` | الصف بلا كود وبلا اسم |
| `save_failed` / `error` | فشل مع رسالة الخطأ وكوده |

في الويب أبلكيشن تُعرض كل حالة **مع سببها بالعربي** في جدول قابل للفلترة،
ويمكن تنزيل الكل كتقرير إكسل من زر «تنزيل تقرير الإكسل».
